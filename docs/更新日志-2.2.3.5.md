# 2.2.3.5 后台过渡模糊修正

用户确认 `2.2.3.4` 已修复可读性底色，但主键盘的毛玻璃仍在手指未松开、应用缩成后台卡片的过程中消失。本次补上宿主延迟清理的保护，作为这一现象的候选修复；尚未通过真机确认全部原因及修复效果。

## 定位依据

在超级小爱输入法 `0.2.1363` APK 中确认：

- `MiInputMethodService.onWindowHidden()` 在非悬浮分支向 Handler 提交延迟 48 毫秒执行的材质清理任务。
- `fb.j0` 的任务回调 `a5.d`（case 3）依次调用 `f()`、`p()`、`q(false)`，并更新宿主自身的状态。
- `f()` 会移除材质 View，触发模块的模糊 Surface 清理；`p()` 清除原生材质效果，`q(false)` 隐藏材质。原有 ThreadLocal 只在 `onWindowHidden()` 调用栈内有效，无法覆盖回调返回后的这些操作。
- 宿主 `onDestroy()` 还会提前执行尚未完成的清理，因此必须在宿主销毁方法进入时解除保护，不能只等父类销毁。

分析 APK 的 SHA-256：`382f6ac9910e71e13d7cb377875996b9e051758307556622fb1a2328a63c23fa`。混淆名称仅用于记录本次证据；实现仍使用现有结构指纹解析的方法与字段。

## 改动

- 隐藏窗口时，用弱引用记录已附着、由主键盘合成器持有的材质与 helper，覆盖异步拆除、材质清理及隐藏调用。
- 主键盘再次显示、开始输入视图、重建或重新挂载材质、配置变化、服务销毁时解除保护。
- 材质被替换或分离、合成器不再持有材质、关闭玻璃效果时，旧保护失效；其他 helper 不继承也不消耗这一保护。
- 补充详细日志，记录隐藏阶段保留材质及拦截拆除的情况。
